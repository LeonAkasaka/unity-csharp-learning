# 型変換と型チェック

継承関係にある型の間で変数を代入・変換する操作を**キャスト**と呼びます。基底クラスへの変換（アップキャスト）と派生クラスへの変換（ダウンキャスト）では、規則が異なります。

## 学習目標

- アップキャストが暗黙的に行える理由を説明できる
- ダウンキャストが明示的な記述を必要とする理由を説明できる
- `is` で型を確認できる
- `as` でキャストして失敗時に `null` を受け取れる
- パターンマッチング `is T x` で型チェックと変数宣言を同時に書ける

## 前提知識

- [継承](/unity-csharp-learning/csharp/inheritance/) を読んでいること

---

## 1. アップキャスト

**書式：アップキャスト**
```
基底クラス型 変数名 = 派生クラスの値;
```

派生クラスのインスタンスを基底クラス型の変数に代入することを**アップキャスト**といいます。暗黙的に行えます。

```csharp
class A { }
class B : A { }

B b = new B();
A a = b;        // アップキャスト（暗黙的）
```

`B` は `A` を継承しているため、`B` のインスタンスは常に `A` として扱えます。

---

## 2. ダウンキャスト

**書式：ダウンキャスト**
```
派生クラス型 変数名 = (派生クラス型)基底クラス変数;
```

基底クラス型の変数を派生クラス型に変換することを**ダウンキャスト**といいます。明示的な記述が必要です。

```csharp
class A { }
class B : A { }

A a = new B();
B b = (B)a;     // ダウンキャスト（明示的）
```

実体が対象の派生クラスでない場合、実行時に `InvalidCastException` が発生します（プログラムがその時点でエラーとなり強制停止します）。

```csharp
class A { }
class B : A { }
class C : A { }

A a = new B();
C c = (C)a;     // ❌ 実行時エラー: a の実体は B であり C ではない
```

---

## 3. `is` 演算子

**書式：`is` 演算子**
```
式 is 型名
```

| 要素 | 説明 |
|---|---|
| `式` | チェック対象の値 |
| `型名` | チェックする型 |

`is` は値が指定した型であるかを `bool` で返します。ダウンキャスト前の確認に使えます。

```csharp
class A { }
class B : A { }

A a = new B();
if (a is B)
{
    B b = (B)a;
}
```

---

## 4. `as` 演算子

**書式：`as` 演算子**
```
式 as 型名
```

| 要素 | 説明 |
|---|---|
| `式` | 変換対象の値 |
| `型名` | 変換先の型 |

`as` はキャストに成功すると変換後の値を返し、失敗すると `null` を返します。例外を発生させず `null` チェックで安全性を確保できる点が特徴です。

```csharp
class A { }
class B : A
{
    public void M() { Console.WriteLine("B.M"); }
}

A a = new B();
B b = a as B;

if (b != null)
{
    b.M();
}
```

```
B.M
```

---

## 5. パターンマッチング（C# 7 以降）

**この書き方は C# 7 から使えます。**

**書式：型パターン**
```
if (式 is 型名 変数名)
{
}
```

| 要素 | 説明 |
|---|---|
| `式` | チェック対象の値 |
| `型名` | チェックする型 |
| `変数名` | チェック成功時にその型として使える変数名 |

型チェックと変数宣言を 1 行に書けます。型が一致したとき `if` ブロック内で変数が有効になります。

```csharp
class A { }
class B : A
{
    public void M() { Console.WriteLine("B.M"); }
}

A a = new B();
if (a is B b)
{
    b.M();
}
```

```
B.M
```

## よくあるミス

```csharp
class A { }
class B : A
{
    public void M() { Console.WriteLine("B.M"); }
}

A a = new B();

// ❌ NG: as の結果が null の可能性を確認しないまま使用する
B b = a as B;
b.M();  // b が null の場合 NullReferenceException が発生する

// ✅ OK: null チェックを行ってから使用する
B b2 = a as B;
if (b2 != null)
{
    b2.M();
}
```

---

## まとめ

- アップキャスト（派生 → 基底）は暗黙的に行える
- ダウンキャスト（基底 → 派生）は `(型)` で明示的に書く。失敗すると `InvalidCastException`
- `is` で型を `bool` チェックできる
- `as` は失敗時に `null` を返す安全なキャスト
- `is T x` のパターンマッチングで型チェックと変数宣言を同時に書ける（C# 7 以降）

---

## 理解度チェック

1. アップキャストはなぜ明示的な記述が不要なのですか？
2. `(B)a` と `a as B` の失敗時の動作の違いを説明してください。
3. 次のコードで `a is B b` が成立するとき、変数 `b` はどのスコープで使えますか？

   ```csharp
   A a = new B();
   if (a is B b)
   {
       // ...
   }
   ```

<details markdown="1">
<summary>解答を見る</summary>

1. 派生クラスは基底クラスのすべてのメンバーを持つため、型安全性が保証されているからです。
2. `(B)a` は失敗すると `InvalidCastException` を発生させます。`a as B` は失敗すると `null` を返します。
3. `if` ブロックの内側です。条件が成立したときのみ `b` が有効になります。

</details>

# スレッドの数と性能

スレッドを増やせば、そのぶん処理が速くなるとは限りません。同時に実行できるスレッドの数は CPU によって決まっていて、それを超えたスレッドは、OS が切り替えながら順番に実行するからです。このページでは、CPU のコアとスレッドの関係、スレッドを切り替える **コンテキストスイッチ**（context switch）、計算するスレッドと待つスレッドの違いを学びます。

## 学習目標

このページを読み終えると、以下のことができるようになります。

- 同時に実行できるスレッドの数が、論理プロセッサーの数で決まることを説明できる
- コンテキストスイッチが何をしていて、なぜコストがかかるのかを説明できる
- 計算するスレッドと待つスレッドで、スレッドを増やしたときの効果が違う理由を説明できる

## 前提知識

- [スレッドの基本](/unity-csharp-learning/csharp/threads/) を読んでいること
- [共有データと lock](/unity-csharp-learning/csharp/thread-safety/) を読んでいること

## 1. CPU のコアとスレッド

CPU の中で、実際に命令を実行する部分を **コア**（core）といいます。基本的に、1 つのコアが同時に実行できるスレッドは 1 つです。

ただし、1 つのコアで 2 つのスレッドを同時に実行できる CPU もあります。この仕組みを **同時マルチスレッディング**（SMT）といい、Intel の CPU では **ハイパースレッディング** と呼ばれています。この場合、OS からは 1 つのコアが 2 つに見えます。そのため、コアが 8 つある CPU でも、同時に実行できるスレッドは 8 つとは限らず、16 になることがあります。

OS から見た、同時にスレッドを実行できる場所を **論理プロセッサー** といいます。論理プロセッサーの数は、[Environment.ProcessorCount プロパティ](https://learn.microsoft.com/dotnet/api/system.environment.processorcount) で調べられます。

```csharp
Console.WriteLine($"論理プロセッサーの数: {Environment.ProcessorCount}");
```

実行結果の例です。値は実行する環境によって変わります。

```
論理プロセッサーの数: 8
```

スレッドの数が論理プロセッサーの数を超えると、すべてのスレッドを同時には実行できません。残りのスレッドは、順番が回ってくるまで待たされます。

---

## 2. コンテキストスイッチ

OS は、実行するスレッドを短い時間ごとに切り替えます。1 つのスレッドに与えられる短い実行時間を **タイムスライス**（time slice）といいます。論理プロセッサーより多くのスレッドがあっても、どのスレッドも少しずつ進むので、すべてが同時に進んでいるように見えます。[スレッドの基本](/unity-csharp-learning/csharp/threads/) で、出力の順序が実行するたびに変わったのは、この切り替えのタイミングが毎回違うからです。

スレッドを切り替えるとき、OS は、それまで実行していたスレッドの状態（次に実行する命令の位置や、CPU が計算に使っていた値）を保存し、次に実行するスレッドの状態を読み込みます。この切り替えを **コンテキストスイッチ** といいます。

```mermaid
flowchart LR
    A1["スレッド A を実行"] --> S1["A の状態を保存<br/>B の状態を読み込む"]
    S1 --> B1["スレッド B を実行"]
    B1 --> S2["B の状態を保存<br/>A の状態を読み込む"]
    S2 --> A2["スレッド A を続きから実行"]
    style S1 fill:#fff3e0,stroke:#e65100
    style S2 fill:#fff3e0,stroke:#e65100
```

オレンジの部分は、どちらのスレッドの処理も進んでいない時間です。1 回の切り替えは短い時間で終わりますが、スレッドが多いほど切り替えの回数が増え、その時間が積み重なります。

## 3. 計算するスレッドは、増やしても速くならない

計算を続けるスレッドは、実行している間ずっとコアを使います。このようなスレッドを、論理プロセッサーの数より多く作っても、同時に実行されるのは論理プロセッサーの数までです。

処理にかかった時間は、[Stopwatch クラス](https://learn.microsoft.com/dotnet/api/system.diagnostics.stopwatch) で測れます。`Stopwatch.StartNew` で計測を始め、[ElapsedMilliseconds プロパティ](https://learn.microsoft.com/dotnet/api/system.diagnostics.stopwatch.elapsedmilliseconds) で経過した時間をミリ秒で取得します。`Stopwatch` は `System.Diagnostics` 名前空間にあるので、ファイルの先頭に `using System.Diagnostics;` を書きます。

**書式：[Stopwatch.StartNew メソッド](https://learn.microsoft.com/dotnet/api/system.diagnostics.stopwatch.startnew)**
```csharp
public static Stopwatch StartNew();
```

次のコードは、同じ量の計算を、スレッドの数を変えて分担させ、かかった時間を表示します。計算の量の合計は変わらないので、スレッドの数を 2 倍にすると、1 つのスレッドが受け持つ量は半分になります。

```csharp
using System.Diagnostics;

int[] threadCounts = { 1, 2, 4, 8, 16, 32, 64 };
foreach (int threadCount in threadCounts)
{
    Measure(threadCount);
}

void Measure(int threadCount)
{
    const long Total = 640_000_000;
    long perThread = Total / threadCount;
    double[] results = new double[threadCount];
    Thread[] threads = new Thread[threadCount];

    Stopwatch sw = Stopwatch.StartNew();
    for (int i = 0; i < threadCount; i++)
    {
        int index = i;
        threads[i] = new Thread(() => results[index] = Work(perThread));
        threads[i].Start();
    }
    foreach (Thread t in threads)
    {
        t.Join();
    }
    sw.Stop();

    Console.WriteLine($"スレッド {threadCount,2} 個: {sw.ElapsedMilliseconds} ミリ秒");
}

double Work(long count)
{
    double sum = 0;
    for (long i = 0; i < count; i++)
    {
        sum += Math.Sqrt(i);
    }
    return sum;
}
```

`Work` は、`Math.Sqrt` で平方根を求めて足し合わせるだけの計算です。計算の結果は使いませんが、計算を省略されないように `results` に入れています。

論理プロセッサーが 32 の環境で実行した結果です。時間は環境や実行するたびに変わります。

```
スレッド  1 個: 1754 ミリ秒
スレッド  2 個: 875 ミリ秒
スレッド  4 個: 445 ミリ秒
スレッド  8 個: 302 ミリ秒
スレッド 16 個: 164 ミリ秒
スレッド 32 個: 101 ミリ秒
スレッド 64 個: 105 ミリ秒
```

スレッドが論理プロセッサーの数に近づくまでは、スレッドを増やすほど時間が短くなります。論理プロセッサーの数を超えると、ほとんど変わらなくなります。同時に実行できるスレッドの数が増えていないので、スレッドを増やしても、1 つの論理プロセッサーが複数のスレッドを切り替えながら実行するだけだからです。スレッドが極端に多いと、コンテキストスイッチやスレッドを作るコストのぶん、かえって遅くなることもあります。

この環境では、4 個までは、スレッドを 2 倍にすると時間がほぼ半分になっています。それより多いと、論理プロセッサーの数に届く前でも、半分まではなりません。性能の違うコアを組み合わせた CPU があることや、ワンポイントアドバイスで説明する同時マルチスレッディングによって、論理プロセッサーの 1 つ 1 つの計算の速さは同じとは限らないからです。

論理プロセッサーの数が少ない環境や、ほかのプログラムが CPU を使っている環境では、この傾向がはっきり表れないことがあります。

## 4. 待つスレッドは、コアを使わない

`Thread.Sleep` で止まっているスレッドや、ファイルの読み込みやネットワークの応答を待っているスレッドは、その間コアを使いません。OS は、待っているスレッドを実行の順番から外し、ほかのスレッドにコアを割り当てます。

次のコードは、1 秒間 `Sleep` するだけのスレッドを 100 個作り、すべての終了を待ちます。

```csharp
using System.Diagnostics;

Stopwatch sw = Stopwatch.StartNew();

Thread[] threads = new Thread[100];
for (int i = 0; i < threads.Length; i++)
{
    threads[i] = new Thread(() => Thread.Sleep(1000));
    threads[i].Start();
}
foreach (Thread t in threads)
{
    t.Join();
}

Console.WriteLine($"{sw.ElapsedMilliseconds} ミリ秒");
```

実行結果の例です。時間は環境や実行するたびに変わりますが、1000 ミリ秒を少し超える程度になります。

```
1032 ミリ秒
```

スレッドは論理プロセッサーの数よりずっと多いのに、全体でおよそ 1 秒で終わっています。100 個のスレッドが、コアを取り合わずに同時に待っているからです。

ただし、待っているスレッドも、スタックのメモリは使い続けています。たとえば 10000 件の通信の応答を待つために 10000 個のスレッドを作ると、どのスレッドもほとんど何もしていないのに、10000 個分のメモリが必要になります。待つためだけにスレッドを 1 つ占有するのは、無駄が大きいのです。この問題は、後で学ぶ非同期処理で解決します。

## 5. スレッドを増やしても速くならない理由

ここまでの内容と、[共有データと lock](/unity-csharp-learning/csharp/thread-safety/) で学んだことをまとめると、スレッドを増やしても速くならない理由は次の 3 つです。

| 理由 | 説明 |
|---|---|
| 論理プロセッサーの数 | 同時に実行できるスレッドは、論理プロセッサーの数まで |
| コンテキストスイッチ | スレッドが多いほど切り替えが増え、どのスレッドも進まない時間が増える |
| `lock` による待ち | `lock` の中は同時に 1 つのスレッドしか実行できないので、その部分はスレッドを増やしても速くならない |

計算するスレッドは、論理プロセッサーの数くらいあれば十分です。待つスレッドはコアを使いませんが、メモリを使います。どちらの場合も、スレッドはむやみに増やさないことが大切です。

---

## ワンポイントアドバイス

### 論理プロセッサーが 2 倍でも、速さは 2 倍にならない

同時マルチスレッディングの CPU では、1 つのコアの計算する装置を 2 つのスレッドで分け合います。論理プロセッサーの数がコアの数の 2 倍になっていても、計算の速さが 2 倍になるわけではありません。そのため、3 節の例では、論理プロセッサーの数に届く前の、コアの数を超えたあたりから、時間の短くなり方が小さくなることがあります。

---

## まとめ

- 同時に実行できるスレッドの数は、論理プロセッサーの数まで。`Environment.ProcessorCount` で調べられる
- OS は、スレッドの状態を保存・読み込みして、実行するスレッドを切り替える。これをコンテキストスイッチという
- 計算するスレッドは、論理プロセッサーの数を超えて増やしても速くならない
- 待っているスレッドはコアを使わないが、メモリは使い続ける

## 理解度チェック

1. 論理プロセッサーが 4 の環境で、計算を続けるスレッドを 8 個作りました。同時に実行されるスレッドはいくつですか？残りのスレッドはどうなりますか？
2. コンテキストスイッチで、OS は何を保存し、何を読み込みますか？
3. 1 秒間 `Sleep` するスレッドを 100 個作ったとき、論理プロセッサーの数が 100 より少なくても、全体がおよそ 1 秒で終わるのはなぜですか？

<details markdown="1">
<summary>解答を見る</summary>

1. 同時に実行されるのは 4 つです。残りの 4 つは、OS がスレッドを切り替えることで順番に実行されます。8 つのスレッドが少しずつ交代で進みます。
2. それまで実行していたスレッドの状態（次に実行する命令の位置や、CPU が計算に使っていた値）を保存し、次に実行するスレッドの状態を読み込みます。
3. `Sleep` で止まっているスレッドはコアを使わないからです。100 個のスレッドはコアを取り合わずに同時に待つので、全体の時間は 1 つのスレッドが待つ時間とほぼ同じになります。

</details>
